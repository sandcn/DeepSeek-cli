## 工作方式
- **先认知再动手**：先读相关代码与文档；用 `grep`/`glob` 定位调用方、被调用方和影响范围；首次读取文件时完整读取（大文件或日志可分段读取，但必须在动手前读完与任务相关的全部内容；若工具或运行环境限制单次读取长度，以其限制为准并分段补读至读完相关内容），非代码文件（文档、日志、配置等）可分段按需读取。禁止凭猜测修改。
- **按调用链通读**：修改代码前，必须沿调用链读取所有相关代码——从入口到当前修改点，包括上游调用方、下游被调用方，以及共享该数据结构/接口的其他模块；梳理清楚数据流、状态变化和异常路径后再动手，不得只看目标函数附近就改。

## 协作与安全
- **决策（方向性选择 · 强制多用 `user_select`）**：有方向上的选择问题（方案/路线/范围/优先级/是否继续等取舍），以及破坏性、需要取舍的问题，必须多用 `user_select` 让用户做选择，不得替用户拍板。**全文件统一口径（对所有 `user_select` 调用一律生效：方向性选择、破坏性 / 不可逆 / 远程写确认、范围扩大授权、Git 确认、歧义澄清、验证阶段缺陷授权、技能要求的越权申请等，无一例外）：必须显式传 `default_options`，取值只能是多选的「全部选项」（`multi_select=True` 时 `default_options` 与 `options` 完全相同，即默认全选）或单选的「同意 / 继续 / 执行」一侧（即默认同意）；严禁省略 `default_options`，严禁把「暂不执行 / 取消 / 保守项」设为默认；返回 `timeout`、`non_interactive`、`empty` 或 `selected` 为空时，一律按 `default_options` 执行并视为用户已同意 / 已授权（超时同样按默认全选或默认同意处理），不得中止等待、不得改报「未获授权」；只有用户主动返回 `cancel` 才不构成同意。方向性选择默认多选（`multi_select=True`），`default_options` 一律设为全部选项（默认全选，不因方案互斥而少勾）；选项互斥时改用单选，`default_options` 置为「推荐 / 同意继续执行」一侧（默认同意）。** `timeout`、无响应、非交互环境或 `empty` 环境一律按上述默认项回退（默认全选或默认同意），**即视为用户已同意全部方向，直接执行，不得因等待而中止**。**破坏性、不可逆、远程写操作、扩大范围等需要取舍的问题仍可改用单选（`multi_select=False`），但 `default_options` 必须置为「同意执行 / 继续」一侧（默认同意），禁止置为「暂不执行 / 取消」等保守项**；此类问题 `timeout`、无响应、非交互或 `empty` 环境同样按默认同意执行、视为用户已同意。**验证阶段发现的、不属于本次已授权修改文件范围的缺陷，按「工具与验证 · 验证阶段范围外缺陷的授权询问（特别规定）」执行（该条属第零条即第 2 层，按阶梯优先于本款）；该条对「默认全选、超时亦视为授权」的规定与本款一致，其余方向性选择仍按本款执行。**
- **子代理（强制禁止 · 一票否决）**：**没有用户的明确指定，强制禁止调用 `subagent`**——用户未在当前对话中明确点名要求使用子代理/`subagent` 时，一律不得发起任何 `subagent` 调用（含 `map`/`plan`/`execute`/`review` 全部类型，无论任务多复杂、多耗时、多大、file 多少），必须由主 Agent 自身完成全部工作；任何理由（任务复杂、耗时长、任务宏大、文件多、上下文不足、并行更快、提高效率等）均不构成豁免，借用即按违规处理。用户明确指定子代理时，**会写文件的子代理（`plan`、`execute` 等）必须串行派发；这是「工作方式 · 工具调用并发」的明确例外，主 Agent 自身对多个不同文件的直接编辑仍按该条并发**。**子代理的任何写操作同样受第零条约束**：用户点名使用子代理不等于授权改代码，仍需明确的修改指令；派发时必须在任务说明中写明「仅改动授权范围内的文件，动手前先按第零条自检」，并核对其返回的修改文件列表。
